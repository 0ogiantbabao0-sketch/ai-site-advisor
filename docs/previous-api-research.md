# AI調査の仕組みと制約

## API

OpenAI `POST https://api.openai.com/v1/responses` を使用。`web_search`、`external_web_access: true`、`tool_choice: required`、`include: ["web_search_call.action.sources"]`、Strict JSON Schemaを指定します。`store: false`。gpt-5系ではreasoning effort low、出力上限12,000トークンです。入力は地域120字、希望600字、機種5件、URL5件以内。

実装時に公式openai-nodeのResponses定義を参照しました：
https://github.com/openai/openai-node/blob/master/src/resources/responses/responses.ts

APIキーの有効性、利用枠、選択モデルによるWeb検索と構造化出力の併用は、ユーザーのキー設定後の実APIで確認が必要です。

## 出典の検査

- 応答が完了し、完了したweb_search_callが存在する必要があります。
- providerが返した検索元URL・URL引用・open_page/find_in_pageのURLを収集します。
- 候補の出典URLがこの集合に含まれなければ、その出典を削除します。候補に出典が残らなければ候補自体を削除します。
- ユーザーの指定ドメイン外、認証情報を含むURL、非HTTP(S)、ローカル/数値IP URLを除外します。サーバーがこれらのURLを直接取得する処理はありません。
- ページを開いた実行記録がある場合と、Web検索の参照元だけの場合を分けます。すべてのURLを実際に訪問したとは表示しません。
- 出典との主張の意味的一致、正確性、最新性は独立検証していません。AIの誤読・誤判断の可能性は残ります。

## 点数

| 項目             | 上限 |
| ---------------- | ---: |
| 狙い機種との一致 |   30 |
| 公開実績の根拠   |   25 |
| 対象日との関連   |   20 |
| エリア・アクセス |   15 |
| 情報の新しさ     |   10 |

各項目に候補の有効な出典URLが必要です。上限を超えた点数、重複項目、根拠のない項目は未評価にします。機種未指定の場合の機種一致は未評価。掲載日不明の場合は鮮度を採点しません。

所在地を含む3項目以上で有効な根拠がある場合：

`score = round(100 × 有効項目の獲得点合計 ÷ 有効項目の配点上限合計)`

それ以外はscore=null（評価保留）。未確認を0点とは扱いません。scoreは公開情報の参考評価であり、出玉の統計予測ではありません。

「参考情報あり」は4項目以上・2ドメイン以上、それ以外の採点可能候補は「情報限定」。未採点は「評価保留」。このラベルはソース数・項目数の説明で、情報の真偽の認証や統計的信頼区間ではありません。

## 情報の扱い

入力とサイト本文の指示を信頼しないこと、架空の出玉・抽選・空き台・将来の設置情報を生成しないことを埋め込みプロンプトで指示しています。ページ掲載日不明はnull。未来の掲載日・不正な日付は除外します。調査実行日時はサーバーで付与します。

半径は周辺検索の目安です。座標距離・経路を計算しないため、候補が厳密に円内であることを保証しません。サイトの閲覧制限や認証を回避しません。サイトが検索から取得できない場合は、その情報を評価対象にできません。
